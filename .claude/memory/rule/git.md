# Git 사용 규칙

git 명령을 위험도에 따라 3단계로 다룬다.

## 🔴 절대 실행 금지 — 저장 / 원격 반영

아래처럼 **커밋하거나 서버(원격)에 올리는** 명령은 **실행하지 않는다.**

- `git commit`
- `git merge`
- `git push`
- 그 외 로컬 이력을 확정 저장하거나 원격에 반영하는 모든 명령

## 🟡 허락 필요 — 코드/설정 변경

아래처럼 **작업 트리·이력을 변경하거나 설정을 바꾸는** 명령은, 실행 전에 **사용자에게 허락을 받거나**, **사용자에게 직접 실행해 달라고 요청**한다. (임의 실행 금지)

- `git pull`
- `git reset`
- `git remote` (add/remove/set-url 등 변경)
- `git checkout` / `git switch` / `git restore` (파일·브랜치 변경)
- `git rebase`, `git stash`, `git clean`, `git config` 등 상태/설정을 바꾸는 명령

## 🟢 항상 허용 — 조회 / 비교

읽기 전용으로 **현재/이전 내용을 확인·비교**하는 명령은 **언제나** 실행해도 된다.

- `git log`
- `git diff`
- `git status`, `git show`, `git branch` (목록), `git remote -v` (조회) 등 상태를 바꾸지 않는 조회

## 원칙

- 애매하면 **변경이 일어나는가?**로 판단 → 변경이면 허락, 조회면 허용.
- 커밋/푸시가 필요하면 실행하지 말고 **사용자에게 요청**한다.

> 이 규칙은 확장될 예정 — 추후 DB, Redis 등 기능이 추가되면 관련 룰이 여기 `rule/`에 추가된다.
